# NearRemote · 网页遥控

用 iPhone、iPad 的 Safari 或其他移动浏览器查看、操作同一局域网里的 Windows 电脑。电脑运行主机服务，移动设备只需打开网页。

## 开始使用

需要 Windows 10/11 和 Node.js 20 或更新版本。截图兼容模式无需第三方运行依赖；要使用高帧率视频，需准备仓库 `tools/ffmpeg.exe`（见下文）。

1. 将压缩包完整解压后，双击 `start.bat`。服务在后台静默运行，电脑默认浏览器自动打开管理页 `http://localhost:3211/host`；如果服务已在运行，即使从另一个解压目录启动，也会复用现有实例并打开管理页。
2. 将手机与电脑连接同一 Wi-Fi，在手机 Safari 中打开管理页显示的局域网地址，例如 `http://192.168.1.20:3211`。
3. 首次使用时，在手机上填写管理页里的六位配对码与设备名称，发送配对请求。
4. 回到电脑管理页，核对设备名称与来源 IP，点击「批准」。手机即可显示桌面并开始控制。以后在同一浏览器打开相同地址，会自动连接，无需再次输入配对码。

关闭浏览器或启动窗口不会停止后台服务。要结束程序，双击 `结束遥控.bat` 或 `stop.bat`；正常关闭屏幕采集与视频编码进程，并保留已记住的设备授权。也可以使用：

```powershell
npm start
npm stop
```

需要查看终端日志时可运行 `npm run start:console`（此模式关闭终端会停止服务）。默认端口为 3211；设置环境变量 `REMOTE_PORT` 可更换端口。后台运行日志在 `%APPDATA%\NearRemote\startup-output.log` 和 `startup-error.log`。

启动与结束均不需要管理员权限。同一 Windows 用户、同一授权数据目录下，从任意解压副本执行结束脚本都能正常停止已运行的 NearRemote；不会仅因为目录不同而拒绝，也不会结束其他软件的 Node.js 进程。启动失败时会显示原因和日志路径，不再直接消失。

## 手机上的控制方式

- 桌面预览：点击对应位置发送鼠标点击，拖动可拖拽窗口或选择内容。
- 电脑鼠标：默认显示电脑真实鼠标的位置与常见指针形态，直接移动电脑鼠标时，手机和平板上的指针也会跟随；移动端操作会即时显示指针和点击反馈。可在「画面设置」中关闭「显示电脑鼠标」。单屏、放大和平移后的查看范围仍保持位置对应；鼠标在查看范围外或被 Windows 隐藏时，不会显示假位置。
- 屏幕选择：桌面顶部可切换主屏、副屏或双屏总览。iPad 默认只查看主屏，避免把两块屏幕挤在中间；横屏、竖屏和分屏窗口均可使用。切换查看范围不重启视频，也不更改电脑显示器配置。
- 放大查看：用「＋」「−」或双指捏合在 100%–300% 之间缩放，「适应」恢复原大小。放大后单指默认拖动画面，轻点仍可点击电脑；切换「拖动画面／操作电脑」可决定单指拖动查看区域还是操作电脑窗口。
- 双指滚动：在桌面画面上用两指同向滑动，滚动电脑里的页面；两指拉开或合拢则缩放。双指手势会释放已有鼠标拖动，避免误选中文字。独立触控板区域也支持双指滚动。
- 画质与帧率：点击桌面右上角的调节图标，在「画面设置」中选择高清、超清、原画以及 10/20/30/60/90 帧目标。默认高清、目标 60 帧、自动视频加速，偏好会自动保存；全屏时也能调整。底部显示实际呈现的帧率，设置菜单显示当前传输画面的实际分辨率、模式与估算流量。
- 全屏横向：点击桌面右上角全屏按钮，手机默认横向显示，iPad 默认跟随设备方向。浏览器不支持锁定屏幕方向时会自动旋转页面内的桌面；物理旋转手机后自动适配，不会重复旋转。顶部可切换方向或退出全屏，旋转、单屏查看及放大后的触摸位置仍对应电脑桌面。
- 触控板：单指移动指针，轻点左键，两指滑动滚动页面；也可使用独立左右键及拖动开关。
- 键盘：输入一段文字发送到电脑当前焦点，或使用回车、退格、Tab、方向键等常用按钮。
- 暂停：主动点击暂停后停止查看与控制，直到手动继续。手机临时切后台时暂停并释放鼠标按键，返回前台后默认自动恢复。
- 断开连接：停止当前连接并保留授权，重新打开页面时可以自动连接；主动断开后不会在同一页面自行抢回连接。
- 忘记这台电脑：明确撤销该浏览器授权，下次需要重新输入配对码并在电脑批准。

首次批准后，浏览器长期保存设备标识、名称和配对凭证。默认勾选「自动连接已记住的电脑」：刷新、重开标签页、从后台返回，或电脑服务重新启动后，页面会自动验证并恢复连接。如果服务暂时不可用，会按 2／4／8／15 秒间隔重试，保留授权且不重放旧控制指令。两台设备分别记住自己的授权。同一浏览器重复配对会更新原授权，设备列表保留一条记录。

关闭「自动连接已记住的电脑」后，授权仍保留，可手动恢复。清除浏览器数据、更换浏览器或访问不同 IP/端口时可能需要重新配对；建议收藏同一个地址。隐私浏览或禁用本地存储可能无法长期保存授权。点击「忘记这台电脑并撤销授权」或在电脑管理页撤销设备后，下次才需要重新输入配对码。

## 电脑管理页

`/host` 仅允许从电脑本机的 `localhost` 或 `127.0.0.1` 访问，展示连接地址、短期配对码、待确认请求与已授权设备。可以刷新配对码、单独撤销设备，或一次撤销全部控制权限。管理接口与手机控制接口使用独立凭证。

电脑默认将已批准设备保存到 `%APPDATA%\NearRemote\trusted-devices.json`，只保存凭证的 SHA-256 校验值及设备信息，不保存明文凭证。可设置 `REMOTE_DATA_DIR` 指定授权文件所在目录。文件损坏时服务会给出错误并停止启动，保留原文件供检查。

同目录的 `server-id.json` 保存稳定的电脑标识。后台启动、正常结束或重新启动电脑都不会主动清空设备授权。

在终端调试模式中，也可输入 `approve XXXX`、`deny XXXX`，输入 `revoke all` 紧急撤销所有会话。

## 无法连接时

1. 手机必须使用管理页显示的局域网 IP；`localhost` 只能在服务电脑上使用。
2. 确认设备连接同一路由器，手机没有走移动数据、访客 Wi-Fi 或开启无线隔离。
3. 首次启动时按 Windows 提示允许 Node.js 通过专用网络防火墙，无需关闭整个防火墙。
4. 双击 `start.bat` 重新打开管理页，确认服务已运行。换 Wi-Fi 后 IP 可能变化，需重新查看管理页地址；给电脑在路由器保留固定 IP 可减少地址变化。
5. 电脑必须处于已解锁的交互式桌面。若已配对设备无法恢复，检查浏览器数据是否被清除，或电脑端是否撤销了该设备授权。
6. 不要只把 `start.bat` 拿出来单独运行；请保留同目录的 `scripts`、`public`、`server.js` 等文件。遇到错误时按弹窗的具体原因检查。

## 使用范围

- 主机端目前支持 Windows 10/11。通过 Windows 桌面捕获和 `SendInput` 完成控制。
- 自动模式使用连续 H.264 视频与硬件编码，最高目标 90 帧。组件或浏览器不可用时回退 JPEG 兼容画面（最高目标 30 帧）；选择 10/20 帧也使用截图通道。实际帧率受电脑采集、编码、网络与手机解码影响；暂不提供音频。
- UAC 安全桌面、登录界面、受保护视频及部分高权限窗口不能捕获或控制。
- 当前使用 HTTP，只在可信的家庭局域网使用；不要设置公网端口转发或公网隧道。配对码与控制内容不具备传输加密。
- 服务检查私有 IPv4 来源、Host 和 Origin，控制接口须持有电脑本机批准后签发的随机令牌。断连、暂停及超时均有鼠标按键释放处理。

### 60／90 帧视频加速

在「画面设置」中选「自动（推荐）」和「60 帧 / 秒」或「90 帧 / 秒」。组件已经准备好的电脑会自动使用 Windows DXGI 桌面采集与可用的硬件编码器；启动时探测 NVENC、Media Foundation 硬件编码，均不可用时再尝试 CPU 编码。无需更改显卡驱动或系统设置。90 帧应配合高刷新率移动屏幕与浏览器；源显示器只有 60Hz 时，其独特的新画面更新仍最多每秒 60 次。

iPhone 使用 Safari 的 ManagedMediaSource，其他兼容浏览器使用 MediaSource。旧浏览器、编码器不可用或视频播放失败时，会明确显示「兼容画面」并回退截图。浏览器可能要求轻点「开始播放」；点击后仍保留桌面手势和全屏功能。

视频组件位于 `tools/ffmpeg.exe`，许可与来源说明在同目录。未附带组件的源码副本可在本目录执行 `npm run setup:video`，脚本从 FFmpeg 官方下载页面推荐的 Windows 构建源下载，并校验发布方 SHA-256。也可通过 `REMOTE_FFMPEG` 指定已安装的 FFmpeg。组件准备好后重新启动服务即可。

本机 3840×1200 双屏测试：DXGI＋Media Foundation 硬件编码输出稳定约 59.7 帧/秒；连同本机 HTTP 和浏览器解码，高清约 59.4 帧、原画约 60.1 帧。此结果不代表手机经过 Wi-Fi 后必然达到相同帧率，请以手机页面的实际读数为准。

90 帧档实测：电脑端高清约 90.1、原画约 89.5 帧；包含本机 HTTP 和浏览器解码后约 89–90 帧。当前主屏为 165Hz，副屏为 60Hz，选择主屏更能体现高帧率效果。

### 画质档位

| 档位 | 分辨率上限 | 30／60 帧视频目标码率 | 90 帧视频目标码率 | 兼容截图 JPEG 质量 |
| --- | --- | --- | --- | --- |
| 高清（默认） | 1920×1080 | 12 Mbps | 18 Mbps | 88 |
| 超清 | 2560×1440 | 20 Mbps | 30 Mbps | 92 |
| 原画 | 3840×2160 | 36 Mbps | 54 Mbps | 95 |

「原画」表示尽量保留原桌面分辨率，视频与截图仍有损压缩。

保持原始桌面比例，不会放大小于所选上限的画面。多显示器合成桌面也是按整体比例缩放。例如 3840×1200 的桌面在高清档传输为 1920×600，原画档为 3840×1200。

采集、编码与鼠标键盘输入独立，慢画面不会阻塞输入。视频连续传输，并清理旧缓冲、追上实时画面；兼容截图每次只获取并解码一帧，避免积压。最多允许两台设备同时查看视频，同一授权仅保留一条视频连接。高画质与高帧率会增加电脑负载及局域网流量，可查看实际表现后调整。

## 开发检查

在本目录运行：

```powershell
npm run check
npm test
npm run test:reconnect
npm run test:cursor
npm run package
npm run test:launcher
node scripts/benchmark-capture.mjs
npm run benchmark:video
```

可选真实浏览器验收：安装开发用 Playwright 后运行 `npm run test:browser`；可设置 `PLAYWRIGHT_MODULE` 指向 Playwright 的 `index.mjs`，设置 `BROWSER_EXECUTABLE` 指向本机 Chrome。验收使用合成桌面和模拟输入，不会操作真实桌面，截图输出到 `test-results/remote-control`。

`benchmark-capture.mjs` 只测 Windows 桌面采集、压缩与进程通信，不发送鼠标键盘输入，也不保存截图；结果不包含 Wi-Fi 和手机解码耗时。

`npm run test:video` 使用合成的 60 帧测试图案验收 H.264 播放、模式切换与清理，不捕获真实桌面。`scripts/browser-live-benchmark.mjs` 可在本机测真实桌面到浏览器的帧率，使用模拟输入且不保存桌面视频，需同样配置 Playwright。

将环境变量 `VIDEO_TEST_FPS` 设置为 `90` 可运行 90 帧视频验收和测速；`scripts/probe-video90.mjs` 测量电脑端高清及原画的 90 帧输出。

`scripts/browser-ipad-smoke.mjs` 验收 iPad 横竖屏、Split View、单屏／双屏查看、放大后点击、捏合、平移和双指滚动。设置 `TABLET_TEST=1` 运行 `npm run test:video`，还能验证平板切屏与缩放不重启 60 帧视频通道。测试均使用合成画面及模拟输入。

`npm run package` 生成包含 FFmpeg 的 `NearRemote.zip`，并核对启动器依赖是否齐全。`npm run test:launcher` 将真实 ZIP 解压到两个含中文和空格的临时目录，使用隔离端口和授权数据验证跨目录启动／结束、授权保留、身份拒绝及错误提示，不操作日常使用的实例。

`npm run test:cursor` 使用模拟的电脑鼠标和桌面验证真实位置／形状／按键反馈、查看范围、缩放、全屏、开关以及暂停／撤销后停止采样，不向电脑发送真实鼠标输入。鼠标状态使用独立轻量接口同步，不改变视频编码参数。

本项目是独立的 Windows 主机与手机浏览器遥控软件，启动、测试、屏幕采集和授权文件均在此项目目录内管理。FFmpeg 可执行文件不放在 Git 仓库内；首次使用视频加速时执行 `npm run setup:video` 下载并校验，或手动设置 `REMOTE_FFMPEG`。
